# Published data

The iPhone app synchronizes with this directory over HTTPS from the raw `main`
branch origin:

```text
https://raw.githubusercontent.com/nduworker/oh-tidepool-site/main/
```

No GitHub Pages build is involved in serving these files.

| File | Purpose |
| --- | --- |
| `index.json` | The only unconditional request. Carries independent `media_revision` and `conditions_revision` values plus the `ETag` the app conditions on. |
| `media.json` | Integrity manifest for every reviewed image rendition: path, SHA-256, content type, byte count. |
| `daily-conditions.json` | Optional daily briefing. Absent until an editor or the update agent commits one. |
| `welfare-topics.json` | Optional reviewed education/welfare topics the app rotates as an in-app banner. Written by the private repository's publish workflow, validated against `schemas/welfare-topics.schema.json`, and fetched by the app directly with an `ETag`. It is deliberately not in `index.json`, so publishing it moves no revision and invalidates nothing else. |

The app requests `index.json` on launch and foreground entry. A `304 Not Modified`
ends network work for that refresh; a `200` is compared per component so only a
changed component downloads.

`welfare-topics.json` is served from the same origin but has no entry in
`index.json`: the app conditions on its own `ETag`, and an absent file means
"no topics yet" rather than an error.

## Catalog, images, and credits

The app catalog (`api/public/tidepools`, `api/public/discoveries`), the
renditions in `media/`, `schemas/catalog-policy.json`, and the credits list in
`app-media-credits.html` are all generated from the private backend's reviewed
catalog. Do not edit them here: change the backend (or use the photo portal),
then publish with

```sh
PYTHONPATH=host python3 host/scripts/export_ios_catalog.py --site ../oh-tidepool-site
python3 scripts/build-data-index.py
```

The daily publish workflow runs the same export, so the site follows the
backend automatically. `build-data-index.py` exits non-zero without altering
tracked output on any validation error and preserves `generated_at` when the
regenerated bytes are semantically unchanged.

## Validating

```sh
python3 scripts/validate-public-data.py
```

This is the same read-only check the
[`Validate public data`](../.github/workflows/validate-public-data.yml) workflow
runs. It parses every present document, rejects duplicate JSON keys, enforces the
schema versions and required fields, validates ISO-8601 instants, SHA-256 syntax,
byte counts, safe relative media paths, unique location IDs, and the cross-file
revision agreements. It never rewrites the payload to make it pass. Run it before
committing a daily report.

An extra file in `data/` is not an error: the checker validates the documents it
knows by name and ignores everything else. `welfare-topics.json` is one of those
known documents once the mirrored contract carries its checks, and it is skipped
while the file is absent.

The `schemas/` directory is a byte-identical mirror of the private application
repository's `host/news_agent/schemas/`. Keep them in sync when either changes.

## Daily report rules

- The report is a complete snapshot, never an append-only history.
- `expires_at` is authoritative and explicit. The app re-evaluates it against
  device time on every read, including after a `304` or while offline, so an
  expired report cannot remain current.
- A failed provider run must leave the previous tracked files untouched.
- Commit `daily-conditions.json` and the regenerated `index.json` together. If an
  edge cache briefly serves mismatched revisions, the app rejects the component
  and retries on a later refresh.
- Schema version `2` adds an optional `local_updates` array. An update may only
  carry `official_restriction` or `official_caution` when it cites allowlisted
  Tier A evidence for explicitly mapped locations; everything else is
  `context_only`.
